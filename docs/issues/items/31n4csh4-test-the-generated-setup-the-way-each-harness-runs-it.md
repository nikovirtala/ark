# Test the generated setup the way each harness runs it

## Problem
Every bug in the setup audit passed review and CI: scripts without the execute bit, hook output Claude never sees, an MCP env line that breaks writes, cwd-relative deny rules, and no Kiro files when only `.claude/` exists. The tests compared generated bytes with ark's committed files (R9); none ran the setup the way Claude Code or Kiro runs it.

## Proposal
Add harness conformance tests to the R11 fixtures: run each generated piece as its harness would, and check the result against the format that harness documents.

## Done when
- For each harness, a test runs each configured hook command string from the repository root with that harness's event JSON on stdin, and checks exit code, timing and output format (Claude Code: `additionalContext` JSON for PreToolUse, plain text for SessionStart).
- A test starts each configured MCP server with the env the harness would pass, with `ARK_ON_BEHALF_OF` unset and set, and makes one write through it.
- A test parses each harness config against its documented schema, and checks file modes.
- The session-start hook stays inside the harness's hook timeout on a cold npx cache, or the design says how it avoids running several `npx` downloads at start.
- Hook scripts don't assume `origin/main`; they use the ref numbering uses.
- The design doc records, per harness, the doc page and date each format was checked against, so a later check knows what to compare.
