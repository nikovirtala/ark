issues gets its guardrails. `issues hooks install | uninstall | print | run pre-commit | trailers` registers issues in ark's shared hook shims: pre-commit follows staged renames into scopes (`[hooks] scope_follow_renames`), checks `index.md` (or regenerates and stages it with `[hooks] index = "stage"`) and runs `verify --staged`; commit-msg adds one `Issue`/`Issue-Event` pair per staged issue and event type and `Issue: <current issue>`, and warns about "fixes ?N" without a staged close; pre-push runs `verify --fetch-sources`; post-merge runs the new `issues list --since ORIG_HEAD`, which lists issues closed, reopened or assigned to you since a revision. `[log] index = "committed"` is accepted: `issues index [--check] [--commit]` renders `index.md`, every write keeps it fresh in the same commit, and verify reports a stale one. `verify` checks scope globs (an error only for in-progress issues, so open issues may name planned code), `issue:` code anchors, and stale anchors naming closed issues; `verify --staged` checks every issue when a staged config, template or decision-log change touches them. References into other repositories are checked against ledger's source cache, with `verify --fetch-sources`, `issues sources fetch` and `issues list --source`. `issues scope --follow-renames` and `init`'s removal of an empty `.gitkeep` placeholder are new; the starter config writes `index = "none"` with a comment.

Changed behaviour: default commit subjects name the issue by its title (`docs(issues): open "split the orders service"`, `docs(issues): close ?42 "split the orders service" as won't fix`), a commit sweeping in staged events of other types gets a covering subject (`link and scope ?42 "…"`), `edit`'s action is `edit`, and `unlink` says `from`. A custom `[commit] subject` that 0.1.x accepted is refused at config load if its fixed text leaves fewer than 20 characters for the title at the longest batch action (29 characters).
